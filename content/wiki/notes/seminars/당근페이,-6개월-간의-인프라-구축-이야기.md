### 핀테크 인프라 구축
- 금융 서비스 라이센스 취득을 위한 문서 작업
- 금융 서비스 관련된 감독 규정을 지키기 위한 컴플라이언스 준수
- 보안성과 업무 효율성의 사이에서 적정한 선을 찾아야하는 망 분리
- 금융 서비스 운영에 대한 경험 부족
- IDC가 아닌 클라우드 환경에 인프라 구축
![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d6814d8cf3ffa54c66ac16.png]]
#### 1. 로그인 시스템을 어떻게 구성할 것인가?
- 계정 별로 환경이 분리되어야한다.
- 로그인할 수 있는 인터페이스가 최소화 되어야 한다.
- 계정 탈튀 시 여파를 최소화 해야 한다.
답변 
- 개발 환경은 개발 계정 운영 환경은 운영 계정
- 로그인 은 대표 계정 하나에서만
- 탈취 되어도 볼 수 있는 정보가 없도록
→ security IAM User로 로그인을 한다. 
  → 이 계정은로그인을 위한 계정으로 Dev와 Prod 계정으로 로그인을 하기 위한 계정이다.
  → 아무런 리소스가 없다. 따라서 아무것도 할 수 없다
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d6817b99fdf5a77fcb7f64.png]]
#### 2. 서버 접근을 어떻게 할 것인가?
  AWS Session Manager VS SSH VS Teleport
  Teleport를 사용함
  - RBAC지원
  - Github 인증 연동
  - 세션 레코딩 기능
    - 가장 큰 매력으로 로그인 한 사용자가 어떤 행위를 했는지 레코딩되어 재생이 가능하다
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d681c4b6fde494a883a6fb.png]]
#### 3. 애플리케이션 구성을 어떻게 할 것인가?
  K8S VS EC2 기반
  → 개인적인 생각 : 확장 가능성이 높은 도메인 특성 상 k8s를 도입하는게 맞고, EC2에 비해 효용성 효율성이 좋은 K8S를 쓰지 않을 이유가 없었을듯함
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d681ff8630c72510243d4d.png]]
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d6818097e9cb88f667209e.png]]
#### 4. 배포 파이프라인 구성을 어떻게 할 것 인가?
  EKS를 사용하기로 결정했기 때문에 이에 맞는 도구가 필요하다.
  - GitAction
  - ArgoCD
  - ArgoWorkflow
  발표 세션에서 밝히길, 툴에 대한 운영 경험이 많고 Github과 연계가 손쉬운 툴을 선택했다한다.
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d681e8a18bdf9a58f7793f.png]]
#### 5. 관측 시스템을 어떻게 구성할 것인가?
  기존 SaaS를 사용할 것인가? vs 직접 구축할 것인가?
  컴플라이언스 문제로 SaaS사용 자체가 자유롭지 않다고 한다. 
  직접 구축 → 
  - ElasticStack 
  - ElasticAPM
  - Prometheus
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d6818b8c68dc8497e77c9f.png]]
  → OpenSearch가 있는데 ElasticSearch를 따로 Ec2로 배포한 이유가 궁금하다.
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d6810ca5f6e12ea6e0b9d0.png]]
  ![[_attachments/notion/당근페이,-6개월-간의-인프라-구축-이야기/245172a556d681b09952c98b80f970f0.png]]
  → 대부분 사용해본 경험이 있는 기술들인데 쿠버네티스 환경에 적용해 본적이 없다. 이런 경험이 있으면 좋을 듯 하다.
#### 6. 성능 테스트를 어떻게 진행할 것인가?
  Klocust : 부하 생성 도구인 Iocust 을 k8s기반에서 동작하게 하는 오픈소스
  → 테스트의 목적은?
  - 단순히 최대 성능을 측정하는 형태의 테스트는 목적이 불분명합니다.
테스트를 통해 얻고자 하는 데이터를 분명하게 하는 것이 성능 테스트를 잘 할 수 있는 방법입니다. 
10분 동안 테스트를 통해 99percentile 응답 시간이 100ms이내 일때의 최대 TPS
